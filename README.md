# 公司人员和薪酬管理系统 v2.0

## 项目概述
这是一个功能完善的公司人员和薪酬管理系统，为公司财务部门提供现代化的管理工具，能够在公司发放薪水时，方便财务人员为各职工发放薪水并提供直观的工资统计报表。系统采用彩色UI界面，支持数据持久化，具备完整的增删改查功能。

## ✨ 功能特性

### 人员类型
小型公司主要有四类人员：
- **经理 (Manager)** - 等级4，固定月薪18000元
- **技术人员 (Technican)** - 等级3，按每小时120元领取月薪
- **推销员 (Saleman)** - 等级1，月薪按该推销员当月销售额的4%提成 + 底薪4000元
- **销售经理 (Salemanager)** - 等级2，固定月薪5000元 + 所管辖部门当月销售总额的2%提成

### 核心功能
1. **员工管理**
   - ✅ 添加员工（支持4种职位类型）
   - ✅ 删除员工
   - ✅ 修改员工信息（等级调整，自动重算薪资）
   - ✅ 查看所有员工
   - ✅ 清空所有员工

2. **搜索功能**
   - ✅ 按编号搜索
   - ✅ 按姓名搜索（支持模糊匹配）
   - ✅ 按职位搜索

3. **薪资管理**
   - ✅ 自动计算薪资
   - ✅ 显示工资报表
   - ✅ 薪资统计分析（职位分布、最高/最低薪资）
   - ✅ 导出报表到文件

4. **数据持久化** 🆕
   - ✅ 自动保存员工数据到文件
   - ✅ 启动时自动加载历史数据
   - ✅ 所有修改操作实时保存

5. **用户界面** 🆕
   - ✅ 彩色控制台输出
   - ✅ 精美ASCII艺术欢迎界面
   - ✅ 分级菜单系统
   - ✅ 友好的操作提示

## 🛠️ 技术特点

### 设计模式
- **面向对象设计**：使用继承、多态、虚函数等OOP特性
- **虚继承**：解决销售经理类的菱形继承问题
- **动态多态**：通过基类指针管理不同类型员工
- **单一职责**：每个类专注于特定功能

### 技术亮点
- **自动编号系统**：静态成员变量实现编号自动递增（从2001开始）
- **彩色UI**：Windows API实现16色终端输出
- **数据持久化**：文本文件存储，支持断点续传
- **菜单系统**：支持子菜单嵌套和父菜单返回
- **类型安全**：使用dynamic_cast进行安全的类型转换

## 📖 使用说明

### 主菜单功能
1. **添加员工** - 进入子菜单选择具体职位类型
2. **查看所有员工** - 显示所有员工的基本信息
3. **搜索员工** - 按编号/姓名/职位搜索
4. **修改员工信息** - 修改员工等级并自动重算薪资
5. **显示工资报表** - 显示详细的薪资统计表
6. **薪资统计分析** - 职位分布、薪资极值分析
7. **导出报表到文件** - 将工资报表导出为文本文件
8. **删除员工** - 按编号删除指定员工
9. **清空所有员工** - 删除所有员工数据
10. **退出系统** - 自动保存并退出

### 数据持久化
- **自动保存**：每次添加、删除、修改员工后自动保存到 `data/employees_data.txt`
- **自动加载**：程序启动时自动读取历史数据
- **数据格式**：`职位类型|ID|姓名|等级|额外数据`

## 💡 个人小结

### 技术收获

1. **面向对象设计经验**
   - 深入理解继承、多态、虚函数的实际应用
   - 掌握虚继承解决菱形继承问题的方法
   - 学会使用静态成员变量实现全局状态管理

2. **数据持久化实现**
   - 设计了简单高效的文本文件存储格式
   - 实现了自动保存/加载机制
   - 学会使用 dynamic_cast 进行类型识别和转换

3. **用户界面优化**
   - 使用 Windows API 实现彩色终端输出
   - 设计了分级菜单系统，提升用户体验
   - 学会使用 ASCII 艺术美化界面

### 遇到的挑战

1. **多重继承复杂性**
   - 问题：Salemanager 类同时继承 Manager 和 Saleman，导致菱形继承
   - 解决：使用虚继承避免 Person 基类被重复继承
   - 经验：多重继承需谨慎使用，优先考虑组合模式

2. **Windows 头文件冲突**
   - 问题：`windows.h` 的 `byte` 定义与 C++17 `std::byte` 冲突
   - 解决：使用 `#define _HAS_STD_BYTE 0` 禁用 std::byte
   - 经验：头文件包含顺序很重要，Windows API 相关头文件需优先包含

3. **数据持久化类型识别**
   - 问题：从文件加载时需要根据职位类型创建不同对象
   - 解决：使用字符串标识 + dynamic_cast 进行类型转换
   - 经验：设计良好的数据格式能简化解析逻辑

### 创新点

1. **彩色 UI 系统**
   - 封装 `UIHelper` 类，提供统一的颜色输出接口
   - 使用不同颜色区分成功/错误/警告/信息提示
   - 提升了系统的专业性和易用性

2. **智能搜索功能**

3. **薪资统计分析**

4. **数据自动保存**

   - 用户无感知的数据持久化体验

## 📝 开发笔记

### 关键代码片段

**虚继承解决菱形继承：**
```cpp
class Salemanager : public Manager, public Saleman {
    // Manager 和 Saleman 都虚继承自 Person
    // 确保只有一个 Person 子对象
};
```

**动态类型识别与转换：**
```cpp
if (emp->getType() == "技术人员") {
    Technican* tech = dynamic_cast<Technican*>(emp);
    if (tech) {
        int hours = tech->getWorkHours();
    }
}
```

**彩色输出封装：**
```cpp
UIHelper::printSuccess("操作成功！");  // 绿色
UIHelper::printError("操作失败！");    // 红色
UIHelper::printWarning("警告信息");    // 黄色
UIHelper::printInfo("提示信息");       // 青色
```

### 性能优化

- 使用 `vector<Person*>` 存储员工，支持动态扩展
- 文件 I/O 操作仅在必要时执行
- 菜单系统使用函数指针，避免大量 if-else 判断
